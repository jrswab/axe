### Decisions

- **Toolchain: pin go1.26.10.** Recorded in the milestone entry and the checkpoint decision line. Go 1.26.10 is the version that fixes the standard-library findings (the milestone cites GO-2026-6809 as needing go1.26.10).
- **x/net: upgrade to v0.62.0.** The first fixed version is v0.62.0. v0.61.0 still reports GO-2026-6860 (verified above).
- **`go` directive: `go 1.26.0` (resolves B1, option O4a).** `golang.org/x/net v0.62.0` declares `go 1.26.0`, so `go mod tidy` requires the bump. The `go 1.25.0` directive is not kept. This is a pre-policy compatibility change: the minimum Go version for `pkg/runner` importers rises from 1.25.0 to 1.26.0. It is recorded in `COMPATIBILITY.md` as a second pre-policy exception beside the 1.11.0 `temperature` change (milestone 001). The reason is the security fix GO-2026-6860, which needs x/net v0.62.0. Go supports only its two newest releases.

### CI effects (evidence)

- **`actions/setup-go@v5` reads only the `go` directive.** The v5 installer parses the `go.mod` file with the regex `^go (\d+(\.\d+)*)` and does not read a `toolchain` line (`src/installer.ts`, `parseGoVersionFile`, upstream at tag `v5`: https://github.com/actions/setup-go/blob/v5/src/installer.ts). This is an external source, not a repository path.
- **Current CI uses fixed versions.** Every setup-go step in these two files pins `go-version: '1.24'`: `.github/workflows/go.yml:19`, `.github/workflows/go.yml:32`, `.github/workflows/go.yml:47`, `.github/workflows/smoke-test.yml:19`, `.github/workflows/smoke-test.yml:70`, `.github/workflows/smoke-test.yml:105`, `.github/workflows/smoke-test.yml:164`, `.github/workflows/smoke-test.yml:212`.
- **`release.yml` uses `stable`.** `.github/workflows/release.yml:24` (`go-version: stable`) is not a version read from `go.mod`. It is a setup-go step, so decision Q5 changes it to `go-version-file: go.mod` in milestone 000 (R3). The only other setup-go steps are in `go.yml` and `smoke-test.yml`. A repository-wide search at `be94237` (`rg -n 'setup-go|go-version' .github/workflows/`) finds no other setup-go step and no other Go version read.
- **Effect of the `go` directive.** With `go-version-file: go.mod` and `go 1.26.0`, setup-go installs go1.26.x. It does not install `go1.26.10` directly. The `toolchain go1.26.10` line resolves at build time under `GOTOOLCHAIN=auto`, so the CI jobs need network access to `proxy.golang.org`. The exact patch level is not assumed; a CI run verifies it.

## Failure Modes

1. **Toolchain download unavailable.** `GOTOOLCHAIN=auto` must fetch go1.26.10 from `proxy.golang.org` when the runner or base image is older than go1.26.10. If the download fails in CI or Docker, the build fails with a toolchain error. Mitigation: confirm the proxy is reachable from the CI runner and the Docker build host. Do not add `GOTOOLCHAIN=local` to work around it; that breaks the pin.
2. **govulncheck still reports findings after the upgrade.** Verified not to happen for `v0.62.0` with go1.26.10 in the experiment. If it does (for example, a new advisory), the milestone is not met. Stop and report the GO id; do not add a suppression.
3. **Minimum Go version raised.** `go 1.26.0` makes any tool that reads the directive (setup-go, importers) require 1.26.0. This is the accepted pre-policy change (Decisions). Importers on Go 1.25 cannot build `pkg/runner` after this release.
4. **Read-only cache in tests.** `cmd` tests fail when `~/.cache/axe` is read-only. This is environmental and reproduces on the unmodified baseline.
5. **Lint action version.** The pinned `golangci-lint-action@v7` may install a golangci-lint built with an older Go that cannot read go1.26 code. Verify with a CI run.
