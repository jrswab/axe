# Milestone 002: Contract-valid Bedrock caching

## Context & Constraints

### Scope and current behavior

This specification covers milestone 002 alone of [the milestone record](053_corrected_caching_milestones.md), lines 44–46. Milestone 001 is complete and supplies each Run's independent cache choice; milestone 003 owns verbose cache counts without a budget and broader usage-output work. This document describes intended behavior, not a claim it is implemented. Main is an Agent Run entered through the CLI or public runner; a Nested Run enters through `call_agent`, resolves its own agent and context, and exposes only its Nested Outcome, not internal turns, files or token counts (`GLOSSARY.md:8-25`, `cmd/run.go:45-102`).

The optional `params.cache_enabled` already resolves omitted to true and explicit true or false to that value independently in Main and Nested requests (`internal/agent/agent.go:76-84`, `pkg/runner/run.go:438-452`, `internal/tool/tool.go:246-261`). The existing request boolean and response cache counters suffice; no new caching abstraction is needed (`internal/provider/provider.go:74-101`). Nested task and explicit context are user-message content, separate from the resolved system prompt (`internal/tool/tool.go:170-185,235-261`); Main prompt or supplied history is likewise separate (`pkg/runner/run.go:276-297,430-452`). Caller tool order and conversation semantics must remain unchanged.

Bedrock currently combines text and `cachePoint` in one system object, places the tool checkpoint on `toolConfig` rather than among tools, and sends a bare tool input schema (`internal/provider/bedrock.go:107-134,169-199,238-258`). Its fixture reads the request into the same production representation, so it cannot independently prove the HTTP JSON contract (`internal/provider/bedrock_test.go:629-657`). Required parameter names are appended while ranging over a map (`internal/provider/bedrock.go:238-258`): unstable ordering is a risk to exact static-prefix matching, not an observed cache miss. Bedrock already maps provider-reported reads and writes (`internal/provider/bedrock.go:261-269`); it implements nonstreaming `Send`, not streaming (`internal/provider/bedrock.go:305-361`). No live server failure has been observed or claimed.

The independent AWS [SystemContentBlock](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_SystemContentBlock.html) and [Tool](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Tool.html) references define tagged unions: only one member per object. [ToolConfiguration](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolConfiguration.html), [ToolSpecification](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolSpecification.md), and [ToolInputSchema](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolInputSchema.md) specify tools-array members and the required `inputSchema.json` wrapper, including when no cache checkpoint is used. These and the [AWS caching guide](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html) were retrieved 2026-11-18 UTC and preserved in [contract research](../../.scratch/issue-83/assets/provider-cache-contracts-research.md). Model, API, region and routing determine supported fields, checkpoint counts, minimum cumulative prefix size and TTL; below-minimum prefixes may succeed without being cached. Valid requests do not establish service acceptance for every model or region, eligibility, hits or savings; provider-managed reuse may not be reflected in reported counts.

Main resolves a Bedrock region, exempts it from the ordinary API-key requirement, and discards `Options.APIKey` and `Options.BaseURL` for Bedrock (`pkg/runner/run.go:385-414`; `pkg/runner/credentials_option_test.go:192-254`). Nested currently follows ordinary API-key setup instead (`internal/tool/tool.go:218-233`). The existing region order is `AWS_REGION` → `AWS_DEFAULT_REGION` → `AXE_BEDROCK_REGION` → `[providers.bedrock] region` → empty (`internal/config/config.go:121-145`). The existing credential resolver uses a complete environment access-key/secret pair first, with optional session token; otherwise it reads `AWS_SHARED_CREDENTIALS_FILE` or `~/.aws/credentials`, selects `AWS_PROFILE` or `default`, and requires an access-key/secret pair in that profile (`internal/provider/awscreds.go:18-76`). This is not the full AWS SDK credential chain. Provider construction signs requests with the resolved credentials and region (`internal/provider/bedrock.go:38-62,305-321`).

## Requirements

### R1 — Bedrock static prefix and wire contract

At the HTTP JSON boundary, for each static-input row below, omitted and explicit true resolve to enabled, while explicit false resolves to disabled. Every system and tool array element is a union object containing only its applicable member; preserve original system text, tool specifications and caller tool order.

| Static input | Enabled | Disabled |
| --- | --- | --- |
| Nonempty system, no tools | A text-only system member followed by a separate `cachePoint`-only member with `type: default`; no tool configuration. | The text-only system member; no checkpoint or tool configuration. |
| Empty system, tools | Ordered tool specifications followed by a separate `cachePoint`-only tools-array member with `type: default`; no synthetic system. | Ordered tool specifications; no checkpoint or synthetic system. |
| Nonempty system and tools | Both preceding enabled shapes: a system checkpoint after system text and a tool checkpoint after the tool specifications. | Both preceding disabled shapes, with neither checkpoint. |
| Empty system, no tools | No synthetic system, tool configuration or checkpoint. | No synthetic system, tool configuration or checkpoint. |

Never place a checkpoint directly on `toolConfig`, combine it with `text` or `toolSpec`, or add one to dynamic messages. For every tool, in every cache mode, `toolConfig.tools[].toolSpec.inputSchema.json` contains the object JSON schema, including its properties and required names; `inputSchema` is not the bare schema. Preserve tool names, descriptions, parameter types and descriptions, required versus optional meaning and the remaining request content.

For identical static inputs, repeated requests and later turns with changing tasks, explicit Nested context, user messages, assistant tool calls and tool results retain the same serialized static system and tool prefix. Dynamic content remains in conversation order and is not moved into the static prefix. For multiple tools and multiple required parameters, the required array has each required name exactly once and remains stable across repeated construction and parameter-map insertion or iteration order; preserve caller tool order. Verify these properties on actual HTTP JSON independently of production request types and against the cited AWS contracts, not by decoding into the structs being tested. Exercise all four static rows in both modes, including the disabled schema, and observe changing dynamic content alongside unchanged static material.

### R2 — Independent choice and Main/Nested AWS setup

Both Main and Nested Bedrock Runs apply their own agent's omitted/true/false cache setting to every request, without inheriting the parent's setting. At the request and Run boundaries verify each setting for each path, both opposing parent/Nested choices, and omission on either side; each observed Bedrock request must satisfy R1. Existing non-Bedrock agent choices remain unchanged.

For both paths use the existing Bedrock region and credentials behavior in Context & Constraints, without an ordinary API key. Verify each region precedence level against lower-priority conflicting values, the empty-region failure, complete environment credentials taking precedence over a configured file, optional session token, file fallback for an incomplete environment pair, explicit `AWS_PROFILE` and default profile, `AWS_SHARED_CREDENTIALS_FILE` and default path, and missing file/profile or incomplete file credentials. Missing region or credentials must fail actionably before an inference request; do not silently use an API key as a region or credentials. Preserve the respective Main configuration/runtime error and Nested error-result boundaries; Main retains underlying credential causes, while Nested projects safe actionable credential guidance without local path details. Tests use controlled local credentials and do not depend on a real AWS account.

Main must continue to ignore its APIKey and BaseURL options for Bedrock, and Bedrock provider API-key and base-URL settings must not become a new authentication or endpoint override in Nested. Verify the effective resolved region and signing credentials for both paths without adding a public credentials or endpoint interface. Do not replace the current resolver with the AWS SDK default chain or change precedence, credential source, session-token behavior, or non-Bedrock setup.

### R3 — Usage, failure and compatibility preservation

Retain Bedrock `cacheReadInputTokens` and `cacheWriteInputTokens` as the existing response read/write counts. Verify independently supplied nonzero, zero and omitted usage, plus existing own-Main-Run accumulation across multiple turns; do not invent missing counts, alter input/output accounting, budget behavior, JSON names/types/zero omission, or forward Nested counts to the parent. This does not implement milestone 003's verbose-without-budget behavior.

Preserve request and response semantics, original provider errors and their status/category/message and caller-visible propagation for authentication, bad request, throttling, server errors, cancellation, transport ambiguity and response-read or decode errors. Generic validation errors must not be misclassified as cache-specific. Verify that no cache-disable replay is introduced, including for an ambiguous outcome; distinguish existing configured Main transient retries from cache fallback and retain Nested's direct-send behavior. Keep existing nonstreaming Bedrock behavior, including the existing fallback when streaming is requested, and leave existing Anthropic/OpenAI streaming paths unchanged. Preserve unrelated assertions and tests subject only to the original Q3 and later scoped role and Q4 exceptions above.
