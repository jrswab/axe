### Existing seams and contract findings

- The existing request boolean and response cache counts are sufficient: `internal/provider/provider.go:74-101`; stream events already carry usage to the runner (`pkg/runner/run.go:890-970`). Do not add a new caching abstraction. Main Agent Runs default caching on and honor the agent's explicit setting (`pkg/runner/run.go:438-452`); Nested Runs currently omit it (`internal/tool/tool.go:247-257`). Each Agent Run must independently honor omitted, true, and false settings, including opposite parent/Nested choices. The Nested path resolves its own system context and passes explicit task and context as a user message (`internal/tool/tool.go:170-185,236-255`); preserve that separation and do not move task or conversation history into a static cache prefix.
- Anthropic's current nonempty system hint and empty-system omission are in `internal/provider/anthropic.go:218-265`. The dated [Anthropic caching guide](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) specifies tools → system → messages: a system breakpoint already covers preceding tools. A tools-only request needs contract-backed static-tool prefix coverage; neither system nor tools must produce a synthetic or history breakpoint. Model minima, TTL, breakpoint and availability limits apply; a valid hint is not a hit guarantee. Normal and existing stream usage map reads and writes (`internal/provider/anthropic.go:340-347,477-484,551-559`).
- `internal/provider/anthropic.go:189-196`, `internal/provider/bedrock.go:243-247`, and `internal/provider/openai.go:233-240` append required parameter names while ranging over maps. That incidental order can change a serialized static prefix; it is a risk, not a demonstrated cache miss. Stabilize incidental ordering without changing caller-supplied tool order or conversation semantics.
- Bedrock currently places text and cachePoint in the same system union object and puts cachePoint on toolConfig (`internal/provider/bedrock.go:107-128,164-196`); tool schemas are unwrapped (`internal/provider/bedrock.go:240-258`). The dated AWS [system union](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_SystemContentBlock.html), [tool union](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Tool.html), [tool configuration](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolConfiguration.html), [tool specification](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolSpecification.md), and [input schema](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_ToolInputSchema.md) specify separate system and tools-array union members and `inputSchema.json`. The schema wrapper is required even with caching disabled. The existing fixture decodes into production structs, so it is not an independent wire oracle (`internal/provider/bedrock_test.go:629-657`). No server failure was observed or claimed. Bedrock usage maps reads and writes (`internal/provider/bedrock.go:260-268`); current Axe Bedrock has no streaming path (`internal/provider/bedrock.go:310-365`). The dated [AWS caching guide](https://docs.aws.amazon.com/bedrock/latest/userguide/prompt-caching.html) makes eligibility, supported fields, checkpoint limits, TTL and minimums model/API/region dependent.
- Main Bedrock setup resolves region and exempts Bedrock from the ordinary API-key requirement (`pkg/runner/run.go:393-414`); Nested setup currently follows the ordinary API-key path (`internal/tool/tool.go:218-233`). Preserve existing region precedence: `AWS_REGION`, `AWS_DEFAULT_REGION`, `AXE_<PROVIDER>_REGION`, provider config, then empty (`internal/config/config.go:121-145`), and AWS credential behavior; do not invent a credentials or endpoint interface.
- OpenAI Chat currently sends automatic requests and maps cached reads, not cache writes (`internal/provider/openai.go:265-305,379-384,552-586`). The dated [OpenAI caching guide](https://developers.openai.com/api/docs/guides/prompt-caching) describes rendered-prefix matching; the dated [Chat create reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create.md) and [stream schema](https://developers.openai.com/api/reference/resources/chat/subresources/completions/streaming-events.md) also describe optional explicit controls and write counts. Lookup-boundary descriptions disagree, and write accounting and model coverage remain uncertain; Responses-specific details cannot simply be transferred to Chat. An Axe opt-out does not promise to disable provider-managed automatic caching. An interrupted stream may omit final usage; never invent it.
- MiniMax shares the Anthropic adapter (`internal/provider/minimax.go:13-27`); Atlas Cloud, Cheaper Inference, Eden AI, LiteLLM, Runcrate and Standard Compute share OpenAI behavior (`internal/provider/atlascloud.go:5-28`, `internal/provider/cheaperinference.go:5-29`, `internal/provider/edenai.go:14-44`, `internal/provider/litellm.go:8-40`, `internal/provider/runcrate.go:5-29`, `internal/provider/standardcompute.go:5-29`). LiteLLM opts into cost reporting. These are regression surfaces, not new provider caching contracts. Preserve text and tool streams, optional usage and cost, and errors.
- The runner accumulates provider counts across its own turns and currently prints cache counts only inside the positive-budget verbose branch (`pkg/runner/run.go:574-637,676-683,778-803`); JSON omits zero counts (`pkg/runner/result.go:120-131`). Keep existing token and budget accounting, JSON names, types and meaning, pipeable stdout, and verbose stderr. Counts are provider reports, not savings; neither zero nor nonzero establishes cache eligibility, disabling, write absence, hit guarantees, or monetary savings. Preserve Nested Outcome opacity: no Nested-to-parent counters or aggregation (`GLOSSARY.md:24-25`).

### Resolved decisions, rejected options and constraints

- **Recovery (Q5, approved):** add no new automatic cache-disable retry in this completion; safe replay is unproven. The dated [Anthropic errors](https://platform.claude.com/docs/en/api/errors), [AWS Converse errors](https://docs.aws.amazon.com/bedrock/latest/APIReference/API_runtime_Converse.md), and [OpenAI errors](https://developers.openai.com/api/docs/guides/error-codes.md) did not establish both a stable cache-only discriminator and safe replay, particularly for partial streams or ambiguous transport outcomes. Preserve original and unrelated errors; offer an actionable cache-specific diagnostic only when the cause is actually identifiable. Generic 400s, validation categories, or substring matches are not universal classifiers. Existing generic transient retries remain unchanged (`internal/provider/retry.go:49-99,121-145`); do not replay partial or uncertain outcomes through a new cache fallback. The older preference for a verbose notice on a proven safe fallback is conditional, not a promise to implement one.
- **OpenAI (Q6/Q7, approved):** retain Chat automatic caching and cache-read reporting; defer `prompt_cache_options`, content-level `prompt_cache_breakpoint`, and `cache_write_tokens` mapping to a separate future effort. Anthropic and Bedrock reads and writes remain in scope. Reject new JSON schema, pricing logic, Responses migration, and a guarantee that opting out disables provider-managed caching.
- **Evidence (Q8, approved):** deterministic, independently contract-backed behavioral tests plus applicable existing gates suffice. Credentialed live probes are optional, unexecuted and nonblocking. Contract fixtures establish wire intent, not live acceptance, hit rate, savings or universal model/region support. No new Bedrock streaming or Nested streaming; preserve existing Anthropic/OpenAI streams. Compatible adapters receive regression coverage only. No implementation, credential use, paid calls, deployment or release is authorized by this record.
- **Human-only assertion checkpoint:** before any implementation rewrites contradicted assertions, Jaron must explicitly approve that assertion rewrite; this plan does not grant it. `internal/provider/bedrock_test.go:638-645` expects `len(receivedReq.System) == 1` and `receivedReq.System[0].CachePoint` on that same system object; `internal/provider/bedrock_test.go:652-656` expects `receivedReq.ToolConfig.CachePoint`. These contradict the independently documented union shapes above. The ToolConfig existence assertion and usage assertions (`internal/provider/bedrock_test.go:648-650,659-663`) remain valid; do not weaken them or change user acceptance. This checkpoint is for future implementation, not a blocker to writing this plan.

### Verification policy for future implementation

Use independently documented raw-wire fixtures rather than production structs as the oracle; exercise observable behavior at the relevant seams, incrementally in each vertical slice. Cover omitted/true/false settings for main and Nested Runs, opposite choices, cache-mode and static-prefix variants, stable multi-required schemas, missing/zero/cumulative usage, errors before streaming and after partial output, ambiguous outcomes, and shared-adapter regressions. Preserve unrelated assertions. Documentation accompanies each behavioral slice.

For Go changes run focused touched-package race tests, `go test -race ./...` and `golangci-lint run` (the existing `.agents/factory-gates.json` gates); run `make check` or its constituent `golangci-lint run`, `go test ./...`, and `make apidiff`. Run applicable `CONTRIBUTING.md` checks, including `.agents/scripts/ci-check integrity`, `.agents/scripts/ci-check vet`, and `.agents/scripts/ci-check build`; report every applicable gate not run and why. Docker is unavailable in this sandbox: if applicable, Docker smoke belongs only to a declared host factory gate or a human host step, not a fabricated available gate. No Go gates are required for this Markdown-only plan.

**Optional future probe, not authorization:** obtain separate explicit approval for live requests, cost and credentials. With fresh provider documentation choose an eligible provider, model, API and region; use only existing transports and an identical static prefix with a controlled changing suffix. Observe two sequential turns (warm then read), recording date, model, route, region, settings, provider-reported counts and outcome without secrets. Probe main and/or Nested Runs only as separately authorized. Such observations are point-in-time and never acceptance blockers: zero does not prove disabled caching or absence of writes, and nonzero does not prove savings.
